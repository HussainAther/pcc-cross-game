# Micro-Fighter Integration Protocol

`pcc-micro-fighter` v0.8.0 is incorporated as a **mechanistic spatial laboratory**, not as a completed construct-recovery environment.

## Frozen boundary

The cross-game layer reads frozen Micro-Fighter validation artifacts only. It does not rerun or retune fighter policies. The frozen competitiveness gate remains failed, so Pressure, Control, and Chaos observational construct statuses are all `unresolved`.

## Evidence admitted

- Pressure: replicated space capture, in-range opportunity generation, and defensive-response forcing; damage conversion is not universal.
- Control: a context-specific defense-to-counter intervention partially improves the targeted matchup, while deterministic retreat under sustained threat worsens it. The v0.8 decomposition attributes retreat backfire to initiative forfeiture, ineffective displacement, rapid re-entry, and poor persistence.
- Chaos: no dedicated frozen construct benchmark yet; remains unresolved.

## Interpretation guardrail

Micro-Fighter tests whether PCC-like mechanisms can appear in a spatial competitive domain without cards, dice, wagering, or hidden-information gameplay. Mechanistic support must not be relabeled as observational construct recovery.
